# Support

## Ask a question

For "how do I configure this", "is this expected behaviour", or general usage questions, use
[Q&A Discussions](https://github.com/hexamatic/pihole-mcp/discussions/categories/q-a) rather than
opening an issue. Someone else with the same question will find the answer there later, and an
accepted answer marks the thread resolved for future readers.

## Report a bug or request a feature

Use the [issue tracker](https://github.com/hexamatic/pihole-mcp/issues/new/choose). It has
separate templates for bug reports and feature requests, each asking for the details that speed up
a fix (Pi-hole version, transport, reproduction steps for a bug; the use case for a feature).

## Report a security vulnerability

Do **not** open a public issue. See [SECURITY.md](SECURITY.md) for how to report it privately, and
for the commands to verify a release artefact's signature, SBOM and provenance.

## Contribute

See [CONTRIBUTING.md](CONTRIBUTING.md) for the development setup and workflow. Issues labelled
[`good first issue`](https://github.com/hexamatic/pihole-mcp/labels/good%20first%20issue) or
[`help wanted`](https://github.com/hexamatic/pihole-mcp/labels/help%20wanted) are a good place to
start.
